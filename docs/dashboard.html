Seven-part series — key numbers dashboard

The headline numbers from nodebench → benchdoctor → tracedoctor → regressiondoctor → fitdoctor → telemetrydoctor → servedoctor, in one page. Every value below is copied from a real command run or a real test suite, not estimated — sources are named on each chart.

No simulated numbers on this page. The P2P ratio, the false-positive counts, the launch/exec ratios, the cross-NUMA bandwidth drops, the KV-cache overestimate and the two utilisation readings all come from a real GPU node or a real pytest run; the fixture-based test counts come from re-running each project's suite locally on 2026-09-01. Where a number was an assumption rather than a measurement (e.g. regressiondoctor's default noise floor, or fitdoctor's framework-overhead range), that is called out in the project's own docs — fitdoctor goes further and tags every figure it prints with a basis of measured / spec / derived / assumed, telemetrydoctor tags every column with which arithmetic it supports at all, and servedoctor tags every file with what may be concluded from it and refuses to print a P99 the sample cannot bound. Nothing is smoothed over here.

Test coverage across the seven tools

Re-run locally on 2026-09-01 (pytest -q in each repo): 739 tests, none of them touching a GPU. Each project keeps the version that was wrong, plus a test asserting it is still wrong — that is what the last column is about.

ProjectTests passingWhat the tests caught
nodebench31parsing and cross-check logic for the four measurement modules; the 5%/15% disagreement bars between the PyTorch and native implementations
benchdoctor3913 → 0 self-scan false positives (fixed rule scope, not a smarter regex)
tracedoctor166 findings across 6 fixture captures, 0 on the healthy baseline (case_good_matmul)
regressiondoctor19naive 5% threshold flagged pure noise as a regression → fixed to a noise-floor-aware bar; all 3 synthetic fixture pairs (noise / regression / improvement) classified correctly
fitdoctor1234 of them assert the naive KV-cache formula is still 4× too big on GQA (and still correct on MHA — which is why the bug survived); 1 asserts the cross-card fp8→fp4 ratios are still inconsistent, so NO_DERIVATION would fail loudly the day that changes
telemetrydoctor1956 assert the naive whole-file aggregation is still wrong — per-card peaks summed give 84.64 GB/s against a steady-state 3.86 (21.9× over), and summing a percentage across 8 cards still returns 239.47%; 3 more pin bugs found inside this library by its own tests: a cross-check that was an algebraic identity, a separability floor below what a uniform distribution scores, and a repeat count that was not scoped to the active phases
servedoctor31610 assert the naive summary is still wrong — it prints a P99 where the exact order-statistic interval has no upper bound inside the sample, and a token rate whose value moves with prompt length; 2 of those are controls asserting the request count and the arithmetic mean do agree. 6 more pin bugs found inside this library: an open/closed-loop detector that scored a by-construction closed loop into its own inconclusive band, a steady-state window referenced to a queue spike instead of the median, a utilisation clamp that produced a 398-second queueing floor for a run whose whole tail was 13 seconds, and a Little's Law check that was an identity
Part of a seven-part series: nodebench (measure) → benchdoctor (static checks) → tracedoctor (dynamic checks) → regressiondoctor (regression checks over time) → fitdoctor (what the number should have been) → telemetrydoctor (what arithmetic the number supports) → servedoctor (whether the number is about the server or the load generator).
This page is a static summary; it does not re-run any benchmark. If a number here ever disagrees with the linked repo, the repo is right.
